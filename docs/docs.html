Overview

Egress answers one question: what does it cost to leave a tokenized US stock position, at a stated size, right now. Entering is easy and every venue advertises it. Leaving is the half nobody prices, and on a tokenized equity it is the half that moves, because the share underneath stops trading at the New York close while the token does not.

The project is two halves that never touch. A crawler reads every listed instrument on a fixed interval and appends what it saw to an append-only record. Everything else - the phase table, the validation, the estimator, this site - reads that record afterwards. Collection never imports interpretation, so a change in how a number is read can never change what was recorded.

No credentials anywhere. Every venue endpoint used is public. The crawler runs unattended on a shared runner with nothing to leak. The only secret in the project is the reader key for the desk, and it lives in the serverless function, never in a page.

Quickstart

Python 3.10 or newer, tested on 3.10 through 3.13. No runtime dependencies at all - the standard library does the HTTP, the gzip and the CSV. Ruff and mypy are dev tools, not requirements.

git clone https://github.com/Ritapossible/Egress.git
cd Egress

# one pass over the whole listed universe, written to state/
python -m egress.crawl --once

# what the record holds so far
python -m egress.crawl --coverage

# what leaving 25,000 USDT of TSLA costs, from the live book
python -c "from egress import exitcost; print(exitcost.for_symbol('RTSLAUSDT', 25000))"

# rebuild this site into docs/
python -m egress.page

A continuous record is a long loop rather than a long process: python -m egress.crawl --loop --hours 6 takes a snapshot every 5 minutes for six hours and exits cleanly, which is what the scheduled job on the repository runs.

Architecture

Twelve modules, each with one job, listed in the order data moves through them.

ModuleWhat it does
configPaths, endpoints and the few constants. No key appears here or anywhere else.
marketThe only module that speaks HTTP. A venue that will not answer raises a typed MarketUnavailable, never a bare exception.
universeClassifies every listed instrument by the venue's own symbolType field. Guessing from the symbol name is wrong for dozens of symbols.
sessionsTurns a timestamp into open, overnight, weekend or holiday. Pure arithmetic, no network.
storeThe append-only record. Rows are written first and the snapshot is entered in the manifest second, so a run killed halfway leaves data no reader will trust.
crawlThe loop. Reads the universe, writes a snapshot, sleeps. It never imports sessions or exitcost: collection is separate from interpretation.
exitcostWalks the book from the mid and returns what an exit costs, with a floor where the book ran out and a bound where slicing is involved.
validateHolds displayed size against printed volume, and refuses to compare a symbol whose own two volume feeds disagree.
llmThe reader. Plain English in, a ticker and a size out - never a price, never a cost. Its output is validated against a shape and clamped before anything uses it.
deskThe question answerer. The reader chooses a ticker and a size; every number after that is computed. One venue round trip per question, so the quote, the plan and the max-exit search describe one same book.
factsReads the whole record and assembles the fact set every page renders from. Nothing here fetches; it only interprets what the crawler stored.
pageGenerates this site. Every measured number is interpolated from facts, never typed, so a figure cannot go stale without the record going stale with it.

The reader compiles, the code computes. The language model is only ever asked for a symbol and a notional. It is never asked for a price, a spread or a cost, and it cannot select a ticker that is not listed on the venue right now - resolution is a lookup against the live instrument list, so an invented ticker fails loudly instead of being priced.

Data reference

The record lives in state/. Each snapshot is one gzipped CSV under state/snapshots/, and state/manifest.jsonl holds one JSON line per completed snapshot. A snapshot absent from the manifest is skipped on read even if its file exists.

ColumnMeaning
snap_tsEpoch milliseconds the snapshot was started, stamped once for every row in it.
symbolVenue symbol, for example RTSLAUSDT or BTCUSDT.
bidBest bid at the moment of the read.
askBest ask at the moment of the read.
bid_sizeSize resting at the best bid, in base units.
ask_sizeSize resting at the best ask, in base units.
lastLast traded price reported by the ticker feed.
turnover24hRolling 24h quote turnover for the symbol.
venue_tsThe venue's own timestamp for the quote, which is what phase is decided from.

Current record: 208 snapshots, 366,288 rows, 3 gaps in coverage, across 1,761 listed instruments (1,175 tokenized stocks, 584 crypto pairs).

Silence is not zero. A symbol missing from a snapshot means the venue did not report it, not that its spread was nothing. Missing rows are absent from every median rather than counted as a value.

HTTP API

One endpoint, used by the desk on the front page. It exists because a reader key cannot live in a browser.

POST /api/ask
Content-Type: application/json

  "q": "What does leaving 40,000 USDT of TSLA cost?"

The response states a symbol, the compiled size, the quote walked off the live book, a slicing bound, and a plain-English reading. Every failure is a stated answer rather than an exception: an unreadable question, a ticker that is not listed, or a venue that will not answer each come back as a sentence saying so. Bodies over 4 KB are refused.

Estimated, never observed. Every figure the endpoint returns is marked estimated. It is what the displayed book says an exit would cost, not a fill anyone received.

Limitations

Stated here rather than buried, because a research tool that hides its limits is a marketing tool.

  • A quote is not a fill. Displayed size can be withdrawn before anyone reaches it, and a real order moves the book it was measured against. Every cost here is an estimate of the displayed book.
  • The record is short. The snapshot count behind every table is printed next to it. Nothing here is a claim about the future, and a handful of days is not a study.
  • Replenishment is unobservable from a snapshot. That is why slicing is answered as a best and a worst case rather than a number.
  • Two of the venue's volume feeds disagree on tokenized stocks. Which one is right cannot be settled from outside, so those symbols are excluded from validation and named on the validation page.
  • Idle and phantom liquidity look identical. Displayed size going unconsumed could mean it was withdrawn or that nobody wanted it. This data cannot separate them.
  • Research only. Not advice, not an offer, not a quote.

Glossary

TermMeaning here
bpBasis point, one hundredth of a percent. 100 bp is 1%.
midMidpoint of the best bid and best ask. The reference every cost on this site is measured from.
touchThe top of the book - the best bid and best ask and the size resting on each.
floorA cost marked >: the displayed book ran out before the position did, so the true cost is at least this.
phaseopen, overnight, weekend or holiday, decided from the venue's own timestamp against US equity market hours.
controlThe crypto pairs. Same venue, same engine, same fees, no reason to care whether New York is open.
tokenized stockAn instrument the venue reports with symbolType stock, tracking a US listed share.
